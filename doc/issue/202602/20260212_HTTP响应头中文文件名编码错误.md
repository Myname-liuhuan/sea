# HTTP响应头中文文件名编码错误

## 问题标题
HTTP响应头Content-Disposition中文文件名编码错误

## 问题时间
2026-02-12

## 问题描述

### 场景
在sea-media服务中，用户上传视频文件（文件名包含中文，如"测试视频1.mp4"）后，调用接口提取音频为MP3格式并下载时出错。

### 触发条件
- 文件名包含中文字符
- 在Content-Disposition响应头中直接拼接文件名

### 报错信息
```
The HTTP response header [Content-Disposition] with value [attachment; filename="测试视频1.mp3"] has been removed from the response because it is invalid
java.lang.IllegalArgumentException: The Unicode character [测] at code point [27,979] cannot be encoded as it is outside the permitted range of 0 to 255
    at org.apache.tomcat.util.buf.MessageBytes.toBytesSimple(MessageBytes.java:310)
    at org.apache.tomcat.util.buf.MessageBytes.toBytes(MessageBytes.java:283)
    ...
```

## 问题示例代码

### 错误代码
```java
// VideoController.java
@PostMapping("/extract-audio")
public ResponseEntity<FileSystemResource> extractAudioToMp3(
        @RequestPart("file") MultipartFile videoFile) {

    File audioFile = videoService.extractAudioToMp3(videoFile);
    String originalFilename = videoFile.getOriginalFilename();
    String baseName = originalFilename.substring(0, originalFilename.lastIndexOf("."));
    String downloadFilename = baseName + ".mp3"; // 可能为"测试视频1.mp3"

    return ResponseEntity.ok()
            .header(HttpHeaders.CONTENT_DISPOSITION,
                    "attachment; filename=\"" + downloadFilename + "\"") // 错误：直接拼接中文
            .contentType(MediaType.parseMediaType("audio/mpeg"))
            .contentLength(audioFile.length())
            .body(new FileSystemResource(audioFile));
}
```

## 修改方案 / 解决方法

### 最终解决方案
使用Spring提供的`ContentDisposition`类进行正确的RFC 5987编码：

```java
import java.nio.charset.StandardCharsets;
import org.springframework.http.ContentDisposition;

@PostMapping("/extract-audio")
public ResponseEntity<FileSystemResource> extractAudioToMp3(
        @RequestPart("file") MultipartFile videoFile) {

    File audioFile = videoService.extractAudioToMp3(videoFile);
    String originalFilename = videoFile.getOriginalFilename();
    String baseName = originalFilename.substring(0, originalFilename.lastIndexOf("."));
    String downloadFilename = baseName + ".mp3";

    // 使用 ContentDisposition 正确处理中文文件名编码 (RFC 5987)
    ContentDisposition disposition = ContentDisposition.builder("attachment")
            .filename(downloadFilename, StandardCharsets.UTF_8)
            .build();

    return ResponseEntity.ok()
            .header(HttpHeaders.CONTENT_DISPOSITION, disposition.toString())
            .contentType(MediaType.parseMediaType("audio/mpeg"))
            .contentLength(audioFile.length())
            .body(new FileSystemResource(audioFile));
}
```

### 生成的响应头（符合RFC 5987标准）
```
Content-Disposition: attachment; filename*=UTF-8''%E6%B5%8B%E8%AF%95%E8%A7%86%E9%A2%911.mp3
```

### 其他尝试过的方案（不推荐）
1. **URLEncoder编码**：`filename="` + URLEncoder.encode(downloadFilename, "UTF-8") + `"`
   - 问题：不同浏览器处理方式不一致

2. **ISO-8859-1编码**：`new String(filename.getBytes("UTF-8"), "ISO-8859-1")`
   - 问题：不规范，可能导致其他问题

3. **忽略中文**：只使用ASCII字符重命名文件
   - 问题：用户体验差

## 问题原理 / 分析

### 根本原因
HTTP响应头（Headers）遵循**RFC 2616**规范，只允许使用**ASCII字符**（0-255范围）。中文字符"测"的Unicode码点是27979，超出了HTTP响应头允许的字符范围。

### 为什么会报错
1. **HTTP协议限制**：HTTP/1.1响应头必须是ASCII字符
2. **Tomcat验证**：Tomcat在写入响应头时会检查字符编码，发现非ASCII字符时抛出异常
3. **Spring处理**：Spring捕获异常后将该响应头移除，导致下载的文件名变成随机字符串

### RFC 5987标准解决方案
RFC 5987定义了在HTTP响应头中编码非ASCII字符的标准方法：
```
Content-Disposition: attachment; filename*=UTF-8''%E6%B5%8B%E8%AF%95.mp3
                              ^^^^^^^^  ^编码后的内容
                              字符集编码
```

## 经验或注意事项

### 1. 所有文件下载接口都需要注意
- 检查所有使用`Content-Disposition`的代码
- 即使当前文件名是ASCII，也建议使用`ContentDisposition`构建，保持代码一致性
- 本项目中`CodeGenerationController.java`也做了同样的修复

### 2. 类似问题可能出现的场景
| 场景 | 说明 |
|------|------|
| 文件下载 | 任何返回文件、文档、压缩包的接口 |
| 导出功能 | Excel、PDF、CSV等数据导出 |
| 附件上传 | 文件预览、附件下载 |
| API响应 | 自定义响应头中包含用户输入的内容 |

### 3. 排查建议
```bash
# 搜索可能存在问题的代码
grep -r "Content-Disposition" --include="*.java"
grep -r "\.header.*filename" --include="*.java"
```

### 4. 最佳实践
```java
// ✅ 推荐：使用 ContentDisposition
ContentDisposition.builder("attachment")
    .filename(filename, StandardCharsets.UTF_8)
    .build();

// ❌ 不推荐：直接拼接字符串
"attachment; filename=\"" + filename + "\""
```
