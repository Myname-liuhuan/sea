## 核心概念

### 1. RBAC (Role-Based Access Control)
基于角色的访问控制，通过角色来管理用户权限。

### 2. ABAC (Attribute-Based Access Control)
基于属性的访问控制，根据属性动态计算权限。

### 3. DAC (Discretionary Access Control)
自主访问控制，资源所有者决定访问权限。

### 4. MAC (Mandatory Access Control)
强制访问控制，基于安全级别强制实施访问规则。

## 最佳实践

### 1. 权限设计原则
- **最小权限原则**: 只授予必要的权限
- **职责分离原则**: 互斥权限不能分配给同一用户
- **权限继承原则**: 合理设计角色继承关系
- **审计追踪原则**: 记录所有权限变更操作

### 2. 安全开发建议
1. **输入验证**: 对所有用户输入进行验证
2. **输出编码**: 对输出内容进行编码防止XSS
3. **参数化查询**: 使用参数化查询防止SQL注入
4. **错误处理**: 友好的错误信息，不泄露系统细节

### 3. 性能优化
1. **权限缓存**: 缓存用户权限信息
2. **批量查询**: 批量查询权限数据
3. **异步更新**: 异步更新权限缓存
4. **监控告警**: 监控权限系统性能

## 常见问题

### Q1: 如何选择RBAC还是ABAC？
- **RBAC适用**: 组织结构稳定，权限变更不频繁
- **ABAC适用**: 需要动态权限，权限规则复杂多变
- **混合模式**: 结合两者优点，RBAC基础+ABAC扩展

### Q2: 如何处理权限冲突？
- 权限取并集（多个角色权限合并）
- 设置权限优先级
- 使用互斥角色约束
- 权限冲突检测和告警

### Q3: 如何保证权限数据一致性？
- 使用事务保证原子性
- 定期同步权限数据
- 权限变更通知机制
- 数据一致性检查工具
