## 文档规范

### 文件命名
- 主文档: `[主题]-[描述].md` (如: `rbac-design.md`)
- 拓展文档: `[主文档名]-ext-[序号].md` (如: `rbac-design-ext-01.md`)

### 文档结构
每篇文档应包含以下部分：
1. **标题和元信息** (分类、创建日期、最后更新)
2. **相关拓展文档** 链接
3. **正文内容** (分章节组织)
4. **总结和参考资料**

### 拓展文档规范
拓展文档应在开头明确说明：
- **衍生自**: 主文档链接
- **拓展点**: 简要说明拓展内容
- **创建日期**: 文档创建时间

## 贡献指南

### 添加新架构文档
1. 确定文档主题和分类
2. 按照命名规范创建文件
3. 编写完整的文档内容
4. 在本README.md中添加索引
5. 如果需要，创建拓展文档

### 更新现有文档
1. 更新文档内容
2. 更新"最后更新"日期
3. 如果文档结构有重大变化，更新本索引

### 添加拓展文档
1. 确定拓展的主文档
2. 按照命名规范创建拓展文档
3. 在主文档中添加拓展文档链接
4. 在本索引中更新文档关系

## 最佳实践

### 架构设计原则
1. **清晰性**: 架构图清晰，层次分明
2. **可扩展性**: 考虑未来扩展需求
3. **可维护性**: 设计易于理解和维护
4. **安全性**: 安全考虑贯穿设计全过程

### 文档编写建议
1. **图文并茂**: 使用图表辅助说明
2. **示例丰富**: 提供实际应用示例
3. **对比分析**: 对比不同方案的优缺点
4. **实践指导**: 提供具体的实施建议
